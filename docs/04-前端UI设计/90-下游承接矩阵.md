# POM 前端UI-下游承接矩阵

> 把 UI 语义转成 API / DB / 实现可消费的结构化入口。API/DB 文档创建时必须从本矩阵出发覆盖以下最低输出要求。

## 1. 模块承接总表

| 模块 | 分册 | 页面 | 核心对象 | 主要 API 主题 | 主要 DB 对象 |
|------|------|------|----------|---------------|--------------|
| 认证 | A | PAGE-001 | 会话/用户 | auth | user/session |
| 查询 | B | PAGE-002/003 | 报价聚合视图 | quotes/search、quotes/{id}、files | quote/material/requirement/supplier/source_row/batch |
| 导入 | C | PAGE-004~007 | 批次/映射模板 | imports、mapping-templates、batches | batch/source_file/source_row_snapshot/import_row_result/mapping_template |
| 维护 | D | PAGE-008 | 修订 | quotes/{id}(PATCH)、revisions、restore | quote_revision/audit |
| 系统管理 | E | PAGE-009~011 | 用户/审计/备份 | users、audit、admin/backup-status | user/session/audit/backup_meta(文件态) |

## 3. API 设计最低输出要求

- 统一错误模型 {code,message,details} 与错误码表（含 401/403/409/422 语义）
- 认证: POST /auth/login（限速语义：429+剩余时间）、POST /auth/logout、GET /auth/me
- 用户: GET/POST /users、PATCH /users/{id}、POST /users/{id}/reset-password（响应含一次性明文密码）
- 导入: POST /imports/upload（multipart 多文件）、GET /imports/{batchId}/preview（表头识别/映射建议/行级预览/统计）、POST /imports/{batchId}/commit（幂等令牌）、GET /imports/{batchId}/report、POST /mapping-templates、GET /mapping-templates
- 批次: GET /batches、GET /batches/{id}
- 查询: GET /quotes/search（keyword+全部筛选+sort+分页；空结果返回生效条件回显）、GET /quotes/{id}（聚合：物料/需求/供应商/来源/兄弟报价/脱敏）、GET /quotes/{id}/revisions
- 维护: PATCH /quotes/{id}（字段级+reason+乐观锁 version）、DELETE /quotes/{id}、POST /quotes/{id}/restore（admin）、PATCH /quotes/{id}/status
- 文件: GET /files/{id}（鉴权流式下载）
- 管理: GET /audit、GET /admin/backup-status
- 响应规范: 认证接口 Cache-Control: no-store；敏感字段按角色返回明文或脱敏值并标记 masked 字段名列表

## 4. 数据库设计最低输出要求

- 表: user、session、material、purchase_requirement、supplier、quote、import_batch、source_file、source_row_snapshot、quote_revision、audit_log、mapping_template（命名按 db-spec 规范）
- 约束: quote→source_row_snapshot 不可空（可追溯率 100%）；快照表禁止 UPDATE/DELETE 触发器或等价约束；quote.status 字典（03 文档 5.2）；批次事务原子性说明
- 索引: 搜索域（物料名称/编码/规格/品牌/供应商/备注）、报价日期、批次号、审计(操作人/时间/动作)
- 字典: 03 文档 5.2 全部枚举落库为约束或校验
- 方言: 兼容 SQLite 开发/PG 生产（JSON 列、大小写不敏感查询策略）

## 5. 代码实现最低输出要求

- frontend/src: router（含守卫 R-UI-01~04）、stores/auth、api/ 封装（401 拦截/错误统一）、views 按 PAGE-001~011、敏感字段渲染工具、状态/格式化工具（金额/时间/脱敏）
- backend/app: 按 02-架构设计 5.1 模块划分；导入引擎独立包（importers）+ 样例回归测试
- 权限点与前端显隐一致（03 文档 5.1 矩阵为唯一事实源）
