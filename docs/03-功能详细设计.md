## 2. 业务背景与目标

### 2.1 业务背景

采购报价数据分散在几十份 Excel 中，表头位置与字段命名不统一、供应商横向扩列、价格与税费运费混写在备注。使用者查找历史报价依赖记忆逐文件翻查，无法可靠筛选与追溯。本系统把历史表格整理为"物料—需求—供应商—报价—来源"结构化模型，提供统一检索与受控纠错。

### 2.2 目标用户与角色

普通用户（user）
- 用户特征: 采购/设备/生产岗，浏览器查询
- 核心诉求: 快速找到历史报价与来源
- 典型场景: 搜索 → 筛选 → 详情 → 核对来源

数据维护员（maintainer）
- 用户特征: 数据归档责任人
- 核心诉求: 乱表可导、导入前可控、错了可改
- 典型场景: 上传 → 映射 → 预览 → 入库 → 纠错

系统管理员（admin）
- 用户特征: 系统责任人
- 核心诉求: 账号可控、操作可审计、备份可验证
- 典型场景: 用户启停 → 审计查看 → 备份状态

### 2.3 业务目标与成功指标

| 目标 | 指标 | 目标值 | 统计口径 |
|------|------|--------|----------|
| 缩短查找 | 典型查找耗时中位数 | ≤ 2 分钟 | 发起搜索到确认来源 |
| 检索有效 | 查询成功率 | ≥ 80% | 2 分钟内打开有效结果 |
| 导入质量 | 导入覆盖率 | ≥ 95% | 三份样例人工核对 |
| 数据准确 | 关键字段准确率 | ≥ 98% | 人工抽检 |
| 可追溯 | 可追溯率 | 100% | 来源定位字段全量非空 |

### 2.4 约束与假设

- 业务约束: 不做 ERP；不确定识别结果不静默入库（PRD 4.4）
- 权限约束: 不公开注册；查询/维护/管理分权；敏感字段角色化展示（PRD 8.2）
- 合规约束: 密码哈希存储；审计留痕；认证内容禁缓存
- 技术约束: Vue3/FastAPI/PG（生产）/SQLite（开发）；xlrd+openpyxl 解析
- 关键假设: 生产日期取值优先级待业务确认（见 8 待确认）；三份样例代表主要格式形态

### 3.5 业务主链路总览

1. 归档链路: 上传（F-005）→ 识别（F-006）→ 映射（F-007）→ 预览校验（F-008）→ 拆分（F-009）→ 去重（F-010）→ 入库（F-013）→ 报告（F-011），全程快照留底（F-012）

#### 4.1.8 功能项

F-001 登录/退出/会话超时
- 角色/场景: 全部角色；进入系统唯一入口
- 主流程: 提交凭据 → 校验 → 建会话 → 返回令牌与用户信息
- 规则:
  - R-AUTH-01 密码使用 PBKDF2-SHA256（迭代≥60 万）+随机盐，不存明文
  - R-AUTH-02 会话有效期默认 12h，可配置（可维护性要求）
  - R-AUTH-03 退出后令牌立即失效（服务端撤销）
  - R-AUTH-04 登录失败提示统一文案，不泄露账号存在性
- 权限: 公开（仅登录接口）；其余接口全部需要有效会话
- 状态: 会话（active/revoked/expired）
- 页面承接: PAGE-001
- 验收:
  - A-AUTH-01（FR04）退出后携带旧令牌请求返回 401
  - A-AUTH-02（FR01）超时后需重新登录
  - A-AUTH-03（FR03）成功/失败登录均有审计

F-002 用户创建/启停/重置
- 角色/场景: 管理员；账号治理
- 主流程: 新建（随机初始密码）→ 启用使用 → 必要时停用/重置
- 规则:
  - R-AUTH-05 不开放公开注册；仅管理员创建
  - R-AUTH-06 停用立即生效：拒绝新登录并撤销在线会话
  - R-AUTH-07 重置生成随机密码，仅创建/重置时明文展示一次
- 权限: admin
- 状态: 用户（enabled/disabled）
- 页面承接: PAGE-009
- 验收:
  - A-AUTH-04（FR01）停用账号立即无法新建会话，已登录会话在 1 次请求内失效
  - A-AUTH-05（FR02）非管理员访问用户管理 API 返回 403

F-003 角色权限
- 规则:
  - R-AUTH-08 三角色：user（查询/详情）、maintainer（+导入/编辑/标记）、admin（+用户/审计/批次管理/恢复）
  - R-AUTH-09 未授权入口前端隐藏且后端拒绝（双层）
  - R-AUTH-10 敏感字段（电话/地址/银行账户）仅 maintainer/admin 可见明文；user 看脱敏值
- 验收:
  - A-AUTH-06（FR02）user 角色看不到导入/编辑/删除/用户管理入口，直连 API 被 403
  - A-AUTH-07（PRD 8.2）user 查看含电话的详情时电话脱敏

F-004 登录失败限速
- 规则:
  - R-AUTH-11 同一账号连续失败 5 次锁定 15 分钟；同一 IP 每分钟最多 10 次尝试
  - R-AUTH-12 锁定期间即使密码正确也拒绝
- 验收: A-AUTH-08 连续失败触发锁定与倒计时提示

#### 4.2.8 功能项

F-005 Excel 批量上传
- 规则:
  - R-IMP-01 仅接受 .xls/.xlsx；校验文件签名（xls: D0 CF 11 E0；xlsx: PK..）与大小上限（默认 20MB，可配置）
  - R-IMP-02 上传即计算 SHA-256 并登记源文件；文件重命名为随机名+日期目录隔离保存，禁止执行权限
  - R-IMP-03 单文件校验/解析失败不影响其他文件（FR05）
- 页面承接: PAGE-004
- 验收: A-IMP-01（FR05）三份样例 xls 均可读取；A-IMP-02 一个坏文件不影响其余文件结果

F-006 工作表/表头识别
- 规则:
  - R-IMP-04 "导入报价模板"识别特征：存在标题单元格"导入报价模板"+其下"日期:"行+表头行含 ≥3 个标准字段别名 → 表头行自动定位（样例为第 3 行）
  - R-IMP-05 无模板特征的工作表取首个非空行作为候选表头，按别名匹配度打分；低于阈值进入人工选择
  - R-IMP-06 位移检测：若表头首列为"物料编码"等标准字段而数据行首列为连续 1..n 序数，则判定数据列整体右移一列（缺"行号"表头），映射自动左移对齐并提示用户
- 验收: A-IMP-03（FR06）三份样例的"导入报价模板"与"Sheet1"表头均被正确识别（样例1-Sheet1 含位移修正）

F-007 字段映射与模板
- 规则:
  - R-IMP-07 别名映射基于 PRD 7.3 别名表（物料名称/物料描述/商品名称；含税单价/报价/定价/单价；供应商/厂家/品牌厂家/询价方；日期/报价日期/询价日期；数量/需求数量/可供数量）
  - R-IMP-08 "品牌"不自动映射为"供应商"（PRD 7.3 明确）
  - R-IMP-09 "需求数量"与"可供数量"不得互替（PRD 7.3 明确）
  - R-IMP-10 用户确认的映射可保存为映射模板；模板按（文件哈希+表头指纹）自动匹配复用
- 页面承接: PAGE-005
- 验收: A-IMP-04（FR06/07）映射可由用户修正；模板二次导入自动匹配

F-008 行级预览与校验
- 规则:
  - R-IMP-11 预览展示：源行值、映射后标准值、行状态（正常/警告/错误/重复）、拆分后报价数、原因
  - R-IMP-12 清洗边界（PRD 5.4）：去首尾空格、Excel 序列日期转标准日期、纯数字转金额、识别"含税/含运/现货/渠道"关键词；不可靠内容保留原文并标记待确认
  - R-IMP-13 物料描述形如"名称||分类|型号"的管道串：第一段作物料名称候选，整串保留原文
- 验收: A-IMP-05（FR07）预览可见源值/标准值/错误/警告/重复；A-IMP-06 无效价格不被强制转换

F-009 横向多供应商拆分
- 规则:
  - R-IMP-14 映射后仍剩余的非标准列，按"非空文本表头"分组为候选报价组（如"刘/曾/胡"）
  - R-IMP-15 组内提取：金额正则（数字+可选"元"，优先"单价"邻域）；供应商名（含 公司/店/处/厂/专营 等词或列内文本）；电话归敏感字段；渠道关键词（微信/淘宝/京东…）；其余文本入报价备注
  - R-IMP-16 每组生成 0..1 条报价；全部组与物料/需求共享同一原始行快照（FR08）
  - R-IMP-17 提取结果可信度：金额+供应商均有→自动识别；仅部分→待核对；组内仅"等报价/未回"类文本→无有效报价记录（状态）
- 验收: A-IMP-07（FR08）样例2 横向数据拆分后各报价指向同一来源行；A-IMP-08 无有效金额组不生成假价格

F-010 重复检测
- 规则:
  - R-IMP-18 文件级：SHA-256 相同 → 阻止导入并展示既有批次（FR10）
  - R-IMP-19 行级：源文件哈希+工作表+行号+整行内容摘要相同 → 默认跳过
  - R-IMP-20 业务疑似：物料编码/名称+规格+供应商+金额+报价日期 高度一致 → 标记疑似重复供人工确认，不自动覆盖
  - R-IMP-21 MVP 不做自动覆盖/更新（PRD 7.4）
- 验收: A-IMP-09（FR10）重复文件默认不重复导入且可查看原批次

F-011 批次报告
- 规则:
  - R-IMP-22 报告统计：成功/跳过/失败/待确认数量 + 行级原因（FR09）
  - R-IMP-23 入库以批次为单位单事务；失败整体回滚，批次状态=failed（PRD 8.3）
- 验收: A-IMP-10（FR09）报告数量与行级原因一致可查

F-012 原文与快照
- 规则:
  - R-IMP-24 原文件保存至隔离目录并登记哈希；下载需鉴权
  - R-IMP-25 每条报价/需求关联原始行快照：文件名/哈希/工作表/行号/列名→值/上传人/上传时间（PRD 7.2 来源组）
  - R-IMP-26 快照与原文不可被任何修正操作覆盖（PRD FR11）
- 验收: A-IMP-11（FR11）修改结构化字段后原文件与快照不变；A-IMP-12 可追溯率 100%

F-013 结构化入库
- 规则:
  - R-IMP-27 对象关系：物料 1..N 需求 1..N 报价；供应商 1..N 报价；报价关联来源行与批次（PRD 7.1）

## 5. 跨功能通用规则

### 5.1 角色与权限矩阵

| 角色 | 可见模块/对象范围 | 核心可执行操作 | 特殊限制 |
|------|-------------------|----------------|----------|
| user | 搜索/详情/同物料历史 | 查询、筛选、查看详情、下载获授权原文件 | 敏感字段脱敏；无任何写操作 |

| admin | 全部 | 用户管理、批次管理、恢复删除、审计、备份状态 | —（操作均审计） |

### 5.1.1 对象数据范围判定矩阵

- 判定顺序：1. 校验接口权限点（角色）→ 2. 校验对象状态（deleted 仅 admin 可见）→ 3. 敏感字段按角色脱敏

| 对象类型 | 读取判定 | 写入/变更判定 | 补充说明 |
|----------|----------|---------------|----------|
| 报价/物料/供应商 | 全角色；deleted 仅 admin | maintainer+（修订/标记/删除） | 写操作留痕 |
| 导入批次/映射模板 | maintainer+ | maintainer+ | 管理员可查看全部批次 |
| 用户/审计/备份状态 | admin | admin | 敏感操作全审计 |
| 原文件下载 | 全角色（获授权） | — | 下载行为审计 |

| 类型 | 值 | 含义 | 适用范围 |

- 触发事件: 导入提交/修正/删除/恢复/标记/导出/下载/敏感查看
- 通知对象: 无
- 通知方式: N/A
- 审计要求: 记录前后值或对象标识与原因
