## 2. 产品目标与版本策略

### 2.1 产品定位

> 将分散在几十份 Excel 中的采购需求与供应商报价，整理为可集中检索、可追溯到原始文件行号的历史报价资料库；不是完整 ERP。

### 2.2 目标用户

普通用户（查询者）
- 特征描述: 采购/设备/生产相关岗位，人数约 5-10
- 核心诉求: 快速找到某物料/型号的历史报价、供应商和日期
- 使用场景: 浏览器搜索 → 筛选 → 查看详情 → 核对来源

数据维护员
- 特征描述: 负责历史 Excel 归档与数据纠错的人员（MVP 可由管理员兼任）
- 核心诉求: 批量导入不同格式的 Excel，导入前可控，导入后可纠错
- 使用场景: 上传 → 表头识别 → 字段映射 → 预览校验 → 入库 → 异常处理

系统管理员
- 特征描述: 系统与账号责任人
- 核心诉求: 账号可控、操作可审计、数据可备份恢复
- 使用场景: 用户启停、角色分配、批次管理、审计查看、备份状态

### 2.3 业务目标与成功指标

| 目标 | 指标 | 目标值 | 统计口径 |
|------|------|--------|----------|
| 缩短查找时间 | 典型查找耗时中位数 | ≤ 2 分钟 | 从发起搜索到确认报价来源 |
| 提升检索有效性 | 查询成功率 | ≥ 80%（试运行后校准基线） | 搜索后 2 分钟内打开有效结果 |
| 保证导入质量 | 导入覆盖率 | ≥ 95%（三份样例人工核对） | 有效源行成功生成结构化记录占比 |
| 保证数据准确 | 关键字段准确率 | ≥ 98%（人工抽检） | 物料/报价/供应商/来源定位正确比例 |
| 保证可追溯 | 可追溯率 | 100% | 可定位原文件、工作表、行号的记录占比 |
| 持续改善 | 纠错率 | 首期建立基线并持续下降 | 导入后需人工修正记录占比 |

### 2.4 竞争分析（如适用）

替代方案 A：继续用 Excel + 共享网盘
- 优势: 零学习成本、无新系统
- 劣势: 错位列/混合备注导致搜索不可靠；多人维护互相覆盖；无来源追溯
- 差异化策略: POM 保留原始快照与结构化字段并存，兼容历史乱表的同时提供可靠检索

替代方案 B：直接上完整 ERP/SRM
- 优势: 流程完备
- 劣势: 实施周期长、成本高，当前诉求只是历史报价检索
- 差异化策略: POM 明确不做审批/库存/财务，聚焦数据资产化，未来可作 ERP 的报价数据源

### 2.5 版本命名与发布节奏

| 版本类型 | 命名规则 | 发布周期 | 适用场景 | 示例 |
|----------|----------|----------|----------|------|
| 大版本 | V主.次（V1.0 起） | 按里程碑 | 重大能力上线/边界变化 | V1.0 MVP |
| 小版本 | V1.x | 按需（月级） | 功能增强 | V1.1 比较/导出 |
| 补丁版本 | V1.x.y | 按需（周级） | 缺陷修复/映射规则迭代 | V1.0.1 |

### 2.6 兼容性与升级策略

- 数据库结构变更一律使用迁移脚本（Alembic），应用版本与导入规则版本可追踪
- 原始文件与原始行快照一经写入不可覆盖，结构化字段的修正以"新增修订记录"方式保存前后值
- 导入规则（字段别名、映射模板）以配置/数据形式存储，规则迭代不破坏既有批次的重放说明
- 破坏性变更（如重复数据策略从"跳过"改为"并存"）需在版本说明中显式声明并评审

## 4. 当前版本规划（V1.0 MVP）

### 4.1 当前版本概览

- 版本号: V1.0
- 版本名称: MVP 历史报价导入与查询闭环
- 计划发布日期: 待定（PRD 未设定时间窗口；按里程碑推进）
- 目标用户: 普通用户、数据维护员、系统管理员（三类角色）
- 版本主题: 三份样例可导入、结构化可查询、结果可追溯、纠错有审计
- 当前状态: 规划中

### 4.2 当前版本目标

1. 建立授权用户从不同网络浏览器访问的统一报价数据入口（HTTPS + 登录）。
2. 打通"上传 Excel → 识别映射 → 预览校验 → 批次入库 → 搜索 → 详情 → 来源追溯"完整闭环。
3. 三份现有样例 xls 不修改原文件即可完成导入，横向多供应商行正确拆分为多条报价。
4. 每条结构化结果 100% 可定位到原文件、工作表、行号和原始文本；修正/删除全部留痕。

### 4.4 明确不在范围内

功能类
- 内容: 采购审批流、订单、合同、电子签章；仓库出入库盘点；发票对账付款财务；ERP/财务/库存系统对接；微信自动抓取报价；任意格式表格无人确认的 100% 自动导入
- 延后原因: PRD 4.3 明确不做（ERP 类为方向性不做，非延后）
- 计划进入版本: 永不（除非 PRD 重新评审）

技术优化类
- 内容: 搜索集群/微服务拆分；多活部署；对象存储多云适配
- 延后原因: 当前 5-10 用户、2 万条报价，单体足够（PRD 4.4 简单优先）
- 计划进入版本: 视数据规模增长再评估

运营/支撑项
- 内容: 同类比价（F-026）、结果导出（F-027）、移动端深度适配（F-028）
- 延后原因: P1 不阻塞发布（PRD 9.3 功能门槛）
- 计划进入版本: V1.1

- 投入周期: M1 需求确认、M3 抽检、M6 验收、试运行期间持续

运维（可由研发兼任）
- 人数: 0.5
- 核心职责: 服务器/HTTPS/备份/恢复演练
- 投入周期: M5-M6

### 7.2 外部依赖与资源约束

历史 Excel 样本
- 类型: 业务输入
- 用途: 建立并回归导入规则
- 预计就绪时间: 已有三份；上线前需扩大样本
- 风险: 格式差异超出样本覆盖

服务器与域名
- 类型: 基础设施
- 用途: 部署与访问入口
- 预计就绪时间: 待定（PRD 明确为实施决策）
- 风险: 免费域名/服务失效导致访问中断
- 应对: 应用不写死域名，备份独立于域名，预留迁移方案

### 7.3 风险评估

| 风险 | 类型 | 可能性 | 影响程度 | 触发信号 | 缓解措施 | 负责人 |
